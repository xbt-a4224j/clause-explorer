Twenty-one tasks that make the system yours. Each one is a question you answer by running or reading something — the answer is hidden until you've tried.

How to use this

Reading a summary of your own repo produces recognition, not ownership, and an interviewer can hear the difference instantly — recognition sounds like narration, ownership sounds like someone who remembers being annoyed by something. These tasks are built to manufacture the second thing.

The rule: answer out loud before you open the fold. Every task has a hidden self-check. If you open it first, you get my answer and none of the ownership. If you answer wrong and then read, you get the ownership anyway — being wrong and corrected is the strongest form of remembering. The only bad path is reading first.

Prerequisite, once:

cd ~/dev/git/clause-explorer && docker compose up -d
# psql shorthand used throughout — worth aliasing
alias q='docker compose exec -T db psql -U explorer -d explorer -c'

Tracks. A is the data, and it comes first because every architecture question eventually bottoms out in "what's actually in there". B is the code, read in the order a request flows. C is the design arguments — for these you defend a decision rather than describe it. D is adversarial: you try to break your own system, which is the fastest ownership there is.

Time budget. Track A is about 40 minutes and is the highest-yield if you only do one. A+B is a solid half day. All four tracks, done honestly with the folds closed, is a day — and at the end you can be interrogated about this repo by someone hostile.

8Why does hybrid retrieval normalize, and what breaks if it does not?

Read the module docstring, then answer without looking: if you deleted the normalization and kept alpha=0.5, what would the ranking actually be, and why?

Read backend/explorer/retrieval/hybrid.py — docstring, then the scoring function. Then find the test that asserts it.
Check yourself

BM25 scores are unbounded and corpus- and query-dependent — a rare term can produce a 30 where a common one produces a 4. Cosine similarities sit in roughly [0, 1]. Add them raw and BM25's scale swamps the vector term: you get approximately pure BM25, and alpha silently stops meaning anything. It would not error. It would not look broken. It would just quietly stop being hybrid.

That "fails silently rather than loudly" quality is what makes it worth a test, and there is one.

Defends The hybrid-search question — with a mechanism most candidates cannot supply.

9Why does retrieval work with no API key?

Embeddings normally require a paid API on every request. Explain how a fresh clone with no key gets identical retrieval results — and what the code deliberately refuses to do.

Read backend/explorer/retrieval/embeddings.py — the docstring enumerates three cases. The middle one is the design decision.
Check yourself

Embeddings are cached by content hash and the cache file is committed, so hit = vector returned, no API call, no key. Miss with a key = embedded once and held in memory, but it deliberately does not rewrite the committed file — warming is an explicit command (python -m explorer.retrieval.warm_cache).

The reason is the interesting part: a request that quietly modified a version-controlled file would make results depend on who ran what, and the "identical results without a key" guarantee would silently stop being true.

Defends "How would we run this without your API keys?" — a real FDE question about deployment into a customer environment.

10Find the min_n gate. All of it.

Grep for every place the refusal is enforced. Then answer: could a crafted request body disable it?

Run grep -rn "min_n\|_refusal\|refused" backend/explorer/api/ | head -20 — then read each hit.
Check yourself

It is enforced server-side on both the rollup and the drill-through, and checked before any query runs. No request field can disable it, because no such field exists — the request models simply have no knob. That is the correct way to make a control non-negotiable: not validation, absence.

Track C · The arguments

For these, do not describe the decision. Defend it against the strongest objection you can construct, out loud, in under a minute.

14Defend: min_n is a security control

Objection to beat: "That's just a statistical significance threshold with a fancy name." Answer in three sentences.

Check yourself

It does three jobs and only the first is statistical. Statistical honesty, so four deals are not read as a market norm. Extraction-confidence gating, since thin slices are where label quality matters most and is least verifiable. And k-anonymity: an attorney who narrows filters until n=1 has extracted one client's negotiated term through the analytics layer, around the ethical wall, without ever retrieving a document.

The clincher: that is why the refusal applies even in count form. "1 of 1" is exactly as identifying as the document itself, so there is no rendering of a too-small selection that is safe to show.

Defends Your strongest governance story, and it generalizes to any enterprise analytics product.

15Defend: the agent selects instead of writing SQL

Objection to beat: "Modern models write good SQL. You've built a cage that limits what users can ask."

Check yourself

Concede the premise — the models do write decent SQL — and reframe on gradeability. An agent has two independent ways to be wrong: the number, and the definition of the number. Generated SQL can only be compared against another generated query; there is nothing discrete to score, so you cannot tell whether a change made it better. A selection from a fixed vocabulary is one discrete decision, gradeable offline with no database and no model in the loop — which is how measure precision 0.80 exists as a number at all.

Then concede the cost honestly: yes, the question space is bounded by the vocabulary. That is the trade, and it is the right one when the output is a figure a partner puts in a pitch.

Defends The central engineering claim of the project, against its best counterargument.

16Defend: long, not wide

Objection: "A wide table would be faster and simpler to query." What does long actually buy, in changes-per-new-deal-point?

Check yourself

Long makes deal_point_name a Cube dimension, so a 93rd deal point is new rows: no migration, no YAML edit, no UI change. Wide makes it a three-place change every time — schema, semantic layer, frontend — and the corpus already carries 92 distinct names against 152 matters.

Concede the cost: aggregate queries over long data need a filter on the name and are less obvious to read. Worth it, because the schema stops being a bottleneck on domain coverage.

Defends The data-modeling question, with a number attached instead of a principle.

17Defend: absence is a finding

Why does a deal point nobody negotiated render as 0 of 8 rather than being omitted? And why does 6 of 8 never render as 75%?

Check yourself

Once the row disappears, "we checked and it is not there" and "we did not check" look identical — and only one of them is useful to someone building a pitch. Absence is information; a missing row is ambiguity.

On percentages: a percentage implies a precision the sample does not support, and this is a figure a partner quotes out loud. The threshold is configuration, not a constant, so the rendering rule can be tested at its exact edge rather than asserted in prose.

Defends "What does good look like in this domain?" — a product-judgment question disguised as a UI question.
