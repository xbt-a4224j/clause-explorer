## 1 — Retrieval, and turning each half of it off

**Tab: Explore.** Click the Health Care facet, then describe the deal. A **rank by** control
appears under the search box: `Keyword α=0 · Hybrid α=0.5 · Meaning α=1`.

![The rank-by control at α=0, beside a card whose two scores disagree](img/retrieval.png)

```
$ for A in 0 0.5 1; do
    curl -s localhost:8000/comparables -H 'content-type: application/json' -d "{
      \"description\": \"healthcare take-private with a go-shop\",
      \"folio_industry_code\": \"RCSG4k3ah1Pu5YgPexPgOmL\",
      \"alpha\": $A, \"limit\": 3}"
  done

hybrid alpha=0.0 | candidates 26
  1. contract_43   DICERNA PHARMACEUTICALS, INC.     blend=1.000 vec=0.178 bm25=1.000
  2. contract_62   GENMARK DIAGNOSTICS, INC.         blend=0.940 vec=1.000 bm25=0.940
  3. contract_32   CONSTELLATION PHARMACEUTICALS      blend=0.825 vec=0.225 bm25=0.825

hybrid alpha=0.5 | candidates 26
  1. contract_62   GENMARK DIAGNOSTICS, INC.         blend=0.970 vec=1.000 bm25=0.940
  2. contract_142  VIELA BIO, INC.                   blend=0.770 vec=0.734 bm25=0.806
  3. contract_55   FIVE PRIME THERAPEUTICS, INC.     blend=0.596 vec=0.645 bm25=0.547

hybrid alpha=1.0 | candidates 26
  1. contract_62   GENMARK DIAGNOSTICS, INC.         blend=1.000 vec=1.000 bm25=0.940
  2. contract_88   MAGELLAN HEALTH, INC.             blend=0.827 vec=0.827 bm25=0.000
  3. contract_141  VARIAN MEDICAL SYSTEMS, INC.      blend=0.817 vec=0.817 bm25=0.000
```

Keyword alone ranks Dicerna first on a perfect word match against a vector score of 0.178 — the
words matched, the meaning did not. Meaning alone surfaces Magellan and Varian at `bm25 0.000`:
they share no query terms at all. The blend keeps what both halves agree on, and Dicerna falls
from 1st to 4th.

Both halves are min–max normalized per query before blending. BM25 is unbounded and cosine sits in
[0, 1]; on this corpus BM25's spread is roughly 25× cosine's, so blending the raw numbers would
make `alpha` decorative. See `normalize()` and `HybridIndex.search()` in
`backend/explorer/retrieval/hybrid.py`.

**Filter before rank, never after.** The industry filter runs in Postgres and the hybrid index is
built over exactly the survivors, so scores are relative to the requested slice. Ranking the corpus
and dropping out-of-filter results afterwards returns three results for a request for ten, with
scores normalized against a corpus nobody asked about.

## 2 — A question becomes a governed selection

**Tab: Ask.** The vocabulary panel is Cube's `/meta`, read live rather than checked in.

```
$ curl -s localhost:8000/agent/catalog \
    | jq '{measures:(.measures|length), dimensions:(.dimensions|length), label_space}'

{ "measures": 11, "dimensions": 18, "label_space": 29 }
```

![Ask — the vocabulary, and the selection it emits](img/semantic-layer.png)

Those names are the `enum` in the structured-output schema, not an instruction in a prompt, so an
invalid name cannot be decoded. A member outside the vocabulary is rejected before Cube is touched:

```
$ curl -s localhost:8000/agent/run-selection -H 'content-type: application/json' \
    -d '{"measures":["deal_points.n"],"dimensions":["matters.industry_label"],"filters":[]}'

{"error":{"code":"validation_error",
          "message":"'matters.industry_label' is not a known dimension."}}
```

A valid selection returns the exact Cube payload alongside the rows:

```
$ curl -s localhost:8000/agent/run-selection -H 'content-type: application/json' -d '{
    "measures":   ["deal_points.n"],
    "dimensions": ["deal_points.position"],
    "filters":    [{"member":"deal_points.deal_point_name","operator":"equals",
                    "values":["Fiduciary exception: Board determination trigger (no shop)-Answer"]}]}'

"rows": [
  {"deal_points.position": "Superior Offer, or Acquisition Proposal reasonably
                            likely/expected to result in a Superior Offer",
   "deal_points.n": "143"},
  {"deal_points.position": "Acquisition Proposal only",
   "deal_points.n": "8"}
]
```

Adding `comparable_deals.label = "Health Care Industry"` gives 26, all one way. That is a
cross-cube filter resolved in the semantic layer, not in a query the model wrote — the model did
not write one.

## 3 — It declines when it cannot answer

Narrow the same selection to a single agreement:

```
$ curl -s localhost:8000/agent/run-selection -H 'content-type: application/json' -d '{
    "measures":   ["deal_points.n"],
    "dimensions": ["deal_points.position"],
    "filters":    [{"member":"deal_points.deal_point_name","operator":"equals",
                    "values":["Fiduciary exception: Board determination trigger (no shop)-Answer"]},
                   {"member":"comparable_deals.id","operator":"equals","values":["contract_1"]}]}'

{"rows": [], "n": 1, "refused": true, "threshold": 5,
 "message": "n=1 — insufficient to characterize (threshold 5).
             The same gate applies to the dashboard and to a direct API call."}
```

![The query builder refusing a slice of one](img/refusal.png)

Refusal is its own shape, never an empty row list with a 200. "We will not answer this" and "there
is nothing here" are different statements about different things.

`min_n` does three jobs: statistical honesty, extraction-confidence gating, and **k-anonymity** —
an attorney who can filter until n=1 has extracted one client's negotiated term through the
analytics layer, around the ethical wall, without retrieving a document. That is why it is enforced
server-side rather than in the UI.

## 4 — The rollup, and what the drill-through actually shows

**Tab: Deal Terms.** The rollup over the selected set, in counts rather than percentages below
n=30.

![Deal Terms — counts, with the full answer distribution per row](img/deal-terms.png)

![The drill-through, naming a document-scale span for what it is](img/deal-terms-drill.png)

MAUD records *where an answer was found*, which for a holistic deal point is most of the agreement:
median span 4,658 characters, 90th percentile 238,949. Presenting that under the word "clause"
showed a table of contents, so a span wider than `max_clause_chars` is labelled a document-scale
span and shown as a bounded excerpt. Ingest re-anchors each annotation's own quoted text inside its
span where it appears exactly once — 7,476 of 12,937. An excerpt found more than once is a miss,
never a guess, and no offset is ever approximated.

The extraction-confidence gate does **not** fire on this rollup. All 12,937 rows are MAUD
annotations made by lawyers (`is_inferred = false` on every one, measured rather than assumed);
gating gold data on a 0.25-median extractor accuracy would suppress most of the product's own data
on the strength of a number describing something else. See `ROLLUP_IS_GOLD_LABELLED` in
`backend/explorer/api/deal_terms.py` and the test that pins it.

## 5 — Where the extractor may be trusted

**Tab: Trust.**

![Accuracy per deal point on held-out gold](img/trust.png)

```
$ make eval
$ curl -s localhost:8000/admin/calibration \
    | jq '{vocabulary_size, measured_deal_point_count, reportable_count, min_extraction_confidence}'

{ "vocabulary_size": 92, "measured_deal_point_count": 90,
  "reportable_count": 5,  "min_extraction_confidence": 0.7 }
```

5 of 90 measured deal points clear the gate. Median accuracy 0.25; six score zero. 1,701
predictions on 20 held-out matters, $0.854442 on `gpt-4o-mini`, summed from each call's own
`response.usage`.

The gate reads the **lower** bound of the 95% Wilson interval rather than the point estimate, so a
thin sample cannot be flattered past it — 3 of 4 correct reads as 0.75 but its interval reaches
0.30. Thirteen deal points have a point estimate at or above 0.70 and eight of those have intervals
too wide to clear it, which is the gate working rather than a rounding quarrel.

### The review loop reports losses

![Label — the queue, ranked by extractor disagreement](img/label.png)

```
$ PYTHONPATH=backend python -m explorer.evals.calibration
correct 569 of 1701 before, 565 of 1701 after; 6 labels applied, 5 differing
```

Calibration prefers a Label-tab decision over the model's answer for the same pair, then grades it
against MAUD like any other answer — a substitution, not a correction. The number went down because
the extractor was right on four of the six pairs a reviewer touched. A loop that could only report
improvement would be a loop worth distrusting.

What this does not show: every holdout matter already has a lawyer's answer, so a reviewer here can
at best reproduce gold. The loop earns its keep on documents with no gold, where the reviewer's
decision is the only answer there is.
